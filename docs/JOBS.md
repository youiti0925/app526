# 仕事ライン（/hustle/jobs）

依頼が来たら、①〜⑥をアプリとAIだけで進め、人は⑦の承認だけ行う仕組み。

| 段 | 誰がやるか | 中身 |
|---|---|---|
| ① 依頼が入る | 人（1回の貼り付け） | 依頼文と入力の表（CSV）を画面に入れる。各サイトのメッセージはログインが要るので取りに行けない |
| ② 振り分け | アプリ → 迷うときだけ軽いモデル | 手順書のキーワードと入力列で点数をつけ、はっきりしていればAIを使わず決める |
| ③ 手順書 | 無ければ上位モデル | 手順書（許可した操作だけを組み合わせたJSON）と手本（先頭3行を上位モデル自身が作業した正解）を作り、軽いモデルで手本を再現できたら採用（一致率80%以上） |
| ④ 作業 | アプリ＋軽いモデル | 機械でできる操作（表記の統一・抽出・名寄せ・NGリスト除外・ページ取得）が先、AIは必要な所だけ |
| ⑤ 検品 | アプリ＋別の呼び出しの中くらいのモデル | 出力規則（必須・形式・ダミー番号）と、依頼の意図とのずれを見る。AIの答えは原文・出典ページに実在するかを機械で確かめ、無ければ空欄＋要確認 |
| ⑥ やり直し | 1段上のモデル → 上位モデル | AIが原因の要確認が2割を超えたら、その行だけ1段上のモデルでやり直す。それでも駄目なら上位モデルが手順書を改修（最大2回）。元データの問題（ダミー番号など）だけなら改修しない |
| ⑦ 承認 | 人 | 承認・却下・「理由を付けて作り直し」。承認しても送信はしない（納品は各サイトで人が行う） |

承認した行（要確認の付いていないもの）は、その手順書の手本に昇格する。手本が貯まると
「安いモデルで足りるか試す」ボタンで、安い順（Gemini無料枠※ → haiku → sonnet）に手本を再現させ、
95%以上一致した最初のモデルに切り替える。
※ 依頼者の資料から作った手本や、Web調査を含む手順書では Gemini を候補にしない。

## スマホから使う（クラウドの専用会話）

PCもサーバーも使わず、スマホの Claude アプリだけで回す形。

1. 仕事ライン専用の会話（指示は docs/JOB-SESSION.md）に、依頼者のメッセージと表（CSV）を貼る
2. その会話が `node scripts/job.mjs run … --push` を1回実行し、結果の要約と `納品.csv` を送ってくる
3. 「承認」「作り直し: 理由」「却下」と返す

- クラウドの作業場所はしばらく使わないと消えるので、手順書と使用量の記録は `library/` としてGitHubに保存する
  （次の作業場所では起動時に読み戻す）。依頼者の資料から作った手本と、入力・納品物（`outbox/`・`data/`）は保存しない
- 開発用の長い会話で仕事を回さない。会話側が1回動くたびに会話全体を読み直すので、アプリ本体より重くなる
- 実測（同じ型・4行）: コマンド1回で約14秒、haiku 1回＋sonnet 1回、API換算 約$0.02

## 案件判定と提案文（専用会話から）

応募を考えている案件の募集文を専用の会話に貼ると、`node scripts/job.mjs judge` が
自律運転と同じ判定（詐欺・関門・納期・実効時給）をこの1件に回し、提案文まで出す。

- 詐欺・資格が要る仕事・個人情報集めなどの関門はルールで決め、AIが何と言っても通さない
- AIは「作業量の見積り」と「提案文」だけに使う（サブスクの Claude、中くらいのモデル）
- 時給は「あなたが手を動かす時間」（仕事ラインで自動化する前提の工程表）で割る
- 貼り付けた募集文から報酬の総額（「予算: 20,000円」「報酬 2万円」）と応募人数を読む
- 仕事ラインに同じ型の手順書があれば、そう表示する（受注後に自動で処理できる見込み）
- 経歴を登録すると提案文に使う（未登録なら経歴の箇所は【要確認】のまま）。
  経歴と手順書は library/ に控えるが、リポジトリが公開設定ならGitHubには保存しない
- 実測: 募集文1件の判定＋提案文で約20秒、sonnet 2回、API換算 約$0.03

## 手順書で使える操作

機械: normalize / split_address / extract / dedupe / exclude / filter / set / template / fetch_page
AI: ai_extract / ai_classify / ai_rewrite / ai_lookup

- Claude が書いた手順書は保存前に検証する。知らない操作・存在しない列の参照・危ない正規表現は弾く。
  AIが任意のプログラムをサーバーで動かすことはできない。
- ページ取得は robots.txt を守り、社内・ローカルのアドレスには行かない（AIが書いたURLを踏み台にさせない）。
- Web で値を調べるときは、ai_lookup では公式URLだけを探させ、値は fetch_page＋ai_extract で本文から抜く。
  Claude Code の WebFetch はページを小さいモデルで要約してから渡すため、値の取り違えが起きる（調査で確認）。

## 実測（2026-09-28、このリポジトリの開発環境で本物のClaudeを使って計測）

| 依頼 | 中身 | 結果 |
|---|---|---|
| 新しい型（6行） | 問い合わせの会社名・電話・メール・種別の整理 | 上位モデルが手順書を作成し、手本で100%一致。ただし検品側の不具合（下記）で改修が2回余分に走り、AI 14回・計約3.7分・API換算 約$0.42 |
| 慣れた型（6行・別の依頼） | 同じ型の10月分 | 振り分けはAIなし（機械の点数で決定）。haiku 1回（約6秒）＋ sonnet 1回（検品、約12秒）。API換算 約$0.03。5行すべて正しく、要確認0 |

1件目で見つかって直したもの:
- 使用量の記録が、上位・中くらいのモデルの呼び出しまで haiku と記録していた（Claude Code が裏で haiku も呼ぶため）
- 検品AIが、重複で落とした行の番号の飛びを「手順の誤り」と指摘していた
- 元データのダミー番号（03-1234-5678）の要確認で、直す必要のない手順書の改修が走っていた

API換算は同じ量をAPIで使った場合の目安で、サブスクでは請求されない。サブスクの週の上限は数値が公開されていないため、
画面では残り何%かを出さず、時間とトークンの実測だけを出している。

## Excel

- 入力: .xlsx をそのまま読む（専用会話では添付、画面ではファイル選択）。最初の表のあるシートを使い、
  ほかのシートがあれば知らせる（`--sheet` で指定）。日付は YYYY-MM-DD、小数は Excel の表示どおり、
  文字列の電話番号は先頭の0を保つ。日本の Excel が埋め込むふりがなは混ぜない
- 出力: `納品.xlsx`（全セル文字列・見出し固定・フィルター付き）と `確認メモ付き.xlsx`（要確認の行は赤）
- 外部ライブラリは使わず、Node の zlib だけで読み書きする（src/lib/hustle/dataops/xlsx.ts）。
  別の実装（Python の openpyxl）が作ったファイルを読めること、こちらが書いたファイルを openpyxl が読めることを確認済み
- 読めないもの: 古い .xls、パスワード付き、計算結果が保存されていない数式（空になる。値は作らない）

## まだできないこと

- 依頼の取り込みは人の貼り付け（各サイトのメッセージを自動で取りに行くのは規約上やらない）
- 画像・スキャンPDFの読み取り、ログインが必要なサイトからの取得
- Web調査型（1行ごとに検索する）依頼の実測はまだ。1行ごとにAIを呼ぶので、慣れた型でも行数に比例して使用量が増える
- 納品（各サイトへの送信）は人が行う
